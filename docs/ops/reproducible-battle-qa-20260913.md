# 再現可能な会戦QA環境

task_id: reproducible-battle-qa-20260913
担当: プログラム＝Claude Code、仕様・レビュー・コマンド試験＝ChatGPT。Unity画面操作はユーザーの専有時間指定まで待つ。
関連: https://github.com/yamamax55/ginei-game/issues/1045 （高速検証ループ）
親: https://github.com/yamamax55/ginei-game/issues/1043

## 確定仕様
退却、不退転、陣形変更を短時間で再現するEditor専用の検証入口を作る。通常プレイの設定や計算式を変更しない。Unity/Windows版のみ。
固定するのは初期条件と実行する命令。フレーム単位の完全な決定論を保証したと表現しない。seedだけで同一戦闘結果になるとは扱わず、初期スナップショットと許容誤差付き判定を分ける。

### プリセット
1. 退却: 同一軍団の複数艦隊と敵を固定配置。軍団総退却で全配下艦隊の命令状態と実際の退却方向への変位を観測。所属外艦隊を巻き込まない。
2. 不退転: 発動艦隊が効果終了前に失われない条件を準備。発動、効果中、終了、終了後の被弾・敗走を観測。固定条件で結果を強制的に書換えて合格させない。被弾継続と被弾停止を区別できる構成。
3. 陣形変更: 軍団所属と各艦隊旗艦を保持。陣形変更、保持、保持解除、命令優先順位を観測。仕様2（費用・失敗理由UI）の先行実装はしない。

### 共通
- 艦隊ID・軍団所属・指揮権限・艦艇数・提督・初期士気・位置・向き・seedをプリセットとして明示する。UI表記は兵力でなく艦艇数。
- 起動時は準備完了まで一時停止し、PauseManagerとtimeScaleを一致させる。開始・再試行・終了の操作を用意する。既存QA入口を再利用できる所は再利用し巨大な並列実装を避ける。
- 生産・外交・戦況ランダムイベント等、対象外要因は固定QA中だけ隔離し、その条件を画面/ログへ明示。AIを止めた試験と通常AIを使う試験は明確に区別する。自然発火の確認にこのモードを使ったとは報告しない。
- 通常会戦のイベント自然発火は別の観測モードに残す。イベント強制発火を自然発火と扱わない。
- Unity Random.state、時間設定、AI設定、イベント有効状態等の変更はQAセッション内に限定。再起動・シーン離脱・Play停止・準備失敗で後始末し、通常会戦に持ち越さない。
- セーブ、シーン、プレハブ、実提督SOは上書きしない。使い捨てメモリデータを使用。既存未コミット変更とv5を保護。commit/push禁止。
- ログにはプリセット名・seed・run_id・設定・ゲーム内経過時間・実観測結果を含める。MoraleAuditLog/陣形保持記録の既存機能と連携し、400件超による記録喪失を明示する。

## 受入条件
同じプリセットを2回初期化して主要初期値が一致する。異なるseedを区別する。各ケースは実コンポーネント/実命令経路を使用し、生存・実被弾・変位等の実結果を確認する。準備失敗・再試行・終了で状態が漏れない。自然会戦イベントの観測を別途未完了のまま保持する。
純ロジックの検証はEditMode/TestHarness、会戦コンポーネントはPlayModeで試験を用意。コマンド実行はChatGPTへ具体的手順を返す。未実施試験は未実施と報告する。

## 実装前のゲート
ユーザーからデスクトップClaudeは回答済み・編集停止と確認済み。CLIの作業票・状態照合を通過した attempt a2 が実装中。attempt a1 は起動前の状態照合で停止しており、重複起動していない。作業票作成・CLI受付は実装完了ではない。

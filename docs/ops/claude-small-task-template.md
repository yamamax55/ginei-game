# Claude向け小作業票・途中確認・検証障害の標準

2026-09-13 ユーザー承認。プログラムはClaude、レビューと試験コマンド実行はChatGPT。次回のCLI作業票から適用する。実行中a2の依頼ファイルやhashを変更せず、二重起動しない。

## 資料を絞る
最初に読む資料は目的、確定仕様、対象ファイルと関係する入口、最小の対応試験を中心にする。コード案内図から候補を選び、関係のないIssue本文や過去チャット全文を複製しない。リポジトリ共通の必須指示は維持する。ファイルの実在と現在の入口を確認して渡す。
依存先が不明ならその型・呼出元・テストへ範囲を広げる。資料不足を理由に推測で接続しない。調査範囲を広げた理由・追加ファイルを報告する。少数のファイルであっても巨大なファイルの全文を依頼文に転載しない。

## 途中のコンパイル確認
チェックポイントは共有型/APIを追加した後、Game層へ最初に接続した後、最終統合後。変更が小さく同一区切りなら一度にまとめる。チェックのためだけに未完成の壊れた状態を量産しない。
現CLIはRead/Grep/Glob/Edit/WriteのみでClaudeはビルドを実行できない。このため作業票をチェックポイントまでの単位にし、Claudeは子担当を含む編集停止とCLI終了を報告する。state=review_ready、editing_stopped=trueに加え checkpoint と remaining を明記し、機能全体の完成とは表現しない。
ChatGPTは終了結果・同一ID・差分を確認してから対象版をコンパイル/関連試験で確認する。全体コンパイル失敗なら新規変更と既存不具合を切り分ける。次の工程は新しい作業ID/attemptと有効な引継ぎで依頼する。編集中のコンパイル、古いUnity生成csprojによる新規ファイル見落とし、旧アセンブリでの実機合格を避ける。
Unityライセンス・環境などで確認できない場合は検証不能として止め、未確認のまま次の依存工程を進めない。独立した仕様/証拠整理は進めてよい。

## 検証不能の早期報告
認証・入力・環境の障害が出た最初の時点で、作業ID、検証対象、期待動作、実際のエラー、実行時刻、試行内容、証跡、必要な対応を記録する。原因が未確定なら仮説と明示する。
同じ条件・同じ失敗の再試行を繰り返さない。環境や操作条件が変わった、または新しい根拠が得られた時だけ再試行し、その変更を記録する。失敗のない状態でも古い進捗は「状態不明」とし、障害の原因を捏造しない。
CLIが終了せず状態不明なら別ジョブを起動しない。対象PID・開始時刻・既存ログの読み取りを優先し、共有画面を奪わない。
Claudeはblocked/questionと編集停止の実態を報告し、ChatGPTは検証不能・不足情報と次の対応を進捗ページへ表示する。ユーザー操作が必要な場合だけ具体的に依頼する。トークンや認証情報は証跡に含めない。

## 作業票テンプレート
- task_id / attempt_id / 関連Issue:
- 今回の目的と対象範囲（1つの完了可能な単位）:
- 確定仕様・観測可能な合格条件:
- 最初に読むファイルと読む理由:
- 編集所有ファイル / 共有接続仕様:
- 必要な試験（既存名、追加すべきケース、実行担当）:
- 今回のチェックポイント / 次回へ残すこと:
- 終了報告: 変更一覧・差分・実施/未実施試験・残件・編集停止・状態ファイル。
- 調査拡張/検証不能時: 理由・試した条件・証跡・必要な対応。

工程時間は development-timing.md に従いChatGPTが実測/観測区間を記録する。時刻取得機能がないClaudeへ正確な時刻の創作を求めない。

## 1〜2. 変化の記録（Editor 限定・新規）

`Assets/Editor/FormationObservationQaMenu.cs`

会戦が決着して戦略へ自動帰還したあとでも、**標的喪失直後のような一瞬の遷移**を読み返せるようにしました。

| メニュー | 役割 |
|---|---|
| `Ginei/QA: 陣形保持 変化の記録を開始（Play中）` | 記録開始（`DontDestroyOnLoad`＝シーンが替わっても続く） |
| `Ginei/QA: 陣形保持 変化の記録を停止` | 記録係を片付ける（履歴は残る） |
| `Ginei/QA: 陣形保持 変化の記録を出力` | 全文を Console `[陣形保持・変化の記録]` へ |
| `Ginei/QA: 陣形保持 変化の記録を消去` | 履歴を捨てる |

### 記録する項目

安定した識別子（`GameObject` の instance ハッシュ＋`オブジェクト名/提督名`）／フレーム・`unscaledTime`・`timeScale`・暦／
**陣形・保持・指定元・最後に決めた出どころ**／**攻撃標的の有無と識別子**／`override` の出どころ／
**敗走・生存・所属**／**軍団総退却の発令**／該当する通知（陣形・保持・要請を含むもの）。

### ログ洪水を避ける設計

- **変化したときだけ**1行。士気やスキルポイントの**自然な増減では記録しません**
- 意味のある変化が起きた行に **`[スキルP 前 → 後]`** を添えるので、費用の照合はできます
- 変化の直後に出た通知だけを `└ 通知:` としてぶら下げます

```
F1234 t=210.55 ts=1.0 暦=… QA_OWN_QA自軍1/QA自軍1  ★手動標的 喪失(直前=QA敵1)  [スキルP 88.0 → 88.0]  {陣形=円陣 保持=True(直接命令) override=なし 標的=なし 敗走=False 生存=True 所属=QA-自軍団 軍団総退却=False}
```

### 後始末・混入防止

- 履歴は上限 **400行**（超えたら古いものから捨て、捨てたことを出力に明記）
- `playModeStateChanged` を購読し直し（`-=` → `+=`）で二重購読を防止
- **Play に入るたびに履歴を消去**＝次のセッションへ混ざらない
- **Play を抜けるときに記録係を破棄**（履歴は読めるまま残す）

### 観測の限界（出力の先頭にも明記）

Play の**フレームごと**に見ているため、**1フレーム未満で元へ戻る変化は写りません**。
**記録が無いことは「起きなかった」証明になりません。**
記録できなかった遷移を完了扱いにしないでください。

## 3. 残るQA 3項目の手順

いずれも**既存メニュー＋通常UI**で、有限の手数で終わります。
はじめに `Ginei/QA: 陣形保持 変化の記録を開始` を実行しておくと、会戦が終わっても読み返せます。

### (A) 自然敗走の継続

> **断定しない前提**：非交戦の艦は士気0が最初の進行フレームで回復しうることが分かっています
> （`FleetMorale`：非交戦が `routedRecoveryDelay` 4秒続くと `recoveryRate` で回復）。
> **交戦中なら必ず継続する、とは言えません**。観測して判断してください。

1. `Ginei/QA: 指揮権限 検証会戦を開始` → `変化の記録を開始` → Space で再開
2. `QA自軍1` に「陣形 ▸ 円陣」（HUD「円陣（保持・直接命令）」）
3. **敵と交戦させたまま**放置し、被弾で士気が落ちるのを待つ
4. `変化の記録を出力` → **`★敗走 開始` の行があるか**、その後に
   `敗走 解除` が続いていないか（＝継続したか）を読む
5. 同じ行の `★保持 解除` で、敗走にともなって保持が解けたことを確認

### (B) 支援受諾の通知と費用

1. `Ginei/QA: 支援要請 他軍団を協力的にする` → Space で再開
2. `QA他軍1` を選択 →「陣形 ▸ 方陣」→ 系統外なので**要請**になる
3. 数秒後「応じました」
4. `変化の記録を出力` → その艦の行で
   - `★保持 開始` ／ `指定元 なし→支援要請`
   - **`[スキルP 前 → 後]`** で費用が引かれていること（同一陣形なら減らないこと）
   - `└ 通知:` に「要請しました」「応じました」が並ぶこと

### (C) 攻撃完了／標的喪失後の保持

**会戦が決着しても後から読めます**（今回取り逃した観測が拾えます）。

1. `QA自軍1` に「陣形 ▸ 円陣」で保持させる
2. 同じ艦隊を選び、右クリックで `QA敵1` へ攻撃を指示
3. `Ginei/QA: 支援要請 攻撃目標を撃沈する（対象消失の再現）`
   → ダイアログに **「★標的と一致：… が狙っていた艦を沈めました」** と出ることを確認
   （⚠ が出たら、まだ攻撃を指示できていないのでやり直し）
4. 会戦が決着して戦略へ戻ってしまってもよいので、`変化の記録を出力`
5. 期待：`★手動標的 喪失(直前=QA敵1)` と `override … → なし` の行があり、
   **同じ行の `{…}` が `保持=True(直接命令) 陣形=円陣` のまま**であること

## 4. 診断文の断定を修正

依頼どおり**読み方だけ**を正しました（製品の入力実装は変更なし）。

| 修正前 | 修正後 |
|---|---|
| 「どちらも 0 なら、そもそもクリックがアプリへ届いていません（自動入力の制約が濃厚）」 | 「このボタンが押されていないというだけです。**ボタン内部の計数であって生入力が来ていない証明にはなりません**（ポインタがボタン上に無ければ 0 のまま）。生入力の有無は記録で確かめてください」 |
| 「[左押下]/[左離上] が1件も無い → 生の入力がアプリへ届いていない（自動入力の制約）」 | 「**この記録では観測できなかった、という意味**。★OSから届いていない証明ではありません。本記録は Update で見ているため、フレーム間で完結した入力や記録開始前／停止後の入力は写りません」 |
| 「押下と離上のフレーム差が大きい/座標が10px以上動く → ドラッグ扱い」 | 「**座標が10px以上動く**とドラッグ扱いになりうる。★**フレーム差が大きいだけではドラッグとは限りません**（長押しでも座標が動かなければクリック）。判断は移動量で」 |

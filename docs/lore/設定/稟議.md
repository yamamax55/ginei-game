# 稟議（りんぎ）

> 下からの建議が[[官僚|官僚機構]]を通って決裁に至る回路。プレイヤーは全能の神でなく、**人を介してしか動けない**。

## 概要
本作のプレイヤーは、戦場の采配こそ直接振るうが、戦略・政治の決定は**ネームドの提案＝稟議**を介して動かす。下位の者が起案し（建議／上申）、官僚機構を中継して決裁者へ届き、裁可されてはじめて台帳が動く。役職と階級の権限が「誰の提案が通るか」を決め、適任者が居なければ発議すらできない――人事と政治が行動を絞る。

## 起案から決裁まで
- **起案**：役職・階級を持つ者が建議を起こす（[[官僚|文官]]＝内政・外交、[[提督|武官]]＝軍事）。
- **中継**：官僚機構を経るうち、官吏の忠実度や省益の摩擦で**値切られ・歪められる**ことがある。
- **決裁**：プレイヤー勢力は決裁デスクで裁可を仰ぎ、AI勢力は自動裁可。承認されれば台帳（兵力・予算・編制）が動く。
- **越階回路**：目安箱は下位者がプレイヤー（上位）へ直に上申する抜け道にもなる。

## 何が稟議で動くか
- **税・予算**の建議、**艦隊の設立・解散**（建艦余剰の配分／空殻の解隊）など。承認制ゆえ、良案も合議の遅れや省益摩擦で握り潰されうる――[[黎明評議会|合議の遅さ]]の手触りそのもの。

## ゲームデータ参照
- 状態機械は `RingiPipeline`/`WorkflowRules`、台帳は `PetitionLedger`（`Petition`）。配線は `RingiDirector`（税）／`FleetRingiDirector`（編制）＝勢力ごとに検討し、プレイヤーは `DecisionDeck`（決裁デスク）へ。官僚の生存ロール `PetitionFlowRules`・省益摩擦 `MinistryRules.DomainFriction`。提案権限は `OfficeRules.CanPropose`＋階級（`RankSystem`）＋文民統制ゲート（#67）。観測＝Alt+I（稟議）。

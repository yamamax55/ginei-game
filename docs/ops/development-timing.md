# 工程時間の計測（2026-09-13開始）

担当: ChatGPTが観測台帳を管理する。プログラムによる計測補助の追加はClaudeへ依頼する。正本: development-timing-current.json（現在の実測）、development-timing-events.jsonl（観測イベント）。

## 記録と区分
作業ID・attempt・工程・担当・開始/終了/観測時刻・根拠・待ち理由を記録する。時刻は実時計またはランナーの実記録。Claudeが時計を取得できない場合は、ChatGPTが観測時刻を記録し、実際の工程境界は前回確認～今回確認の区間内として扱う。推定の正確な時刻を作らない。
工程: 調査、実装、統合、検証（自動/実機を区別）。待ち: Claude完了待ち、検証開始待ち、認証/環境待ち、画面操作待ち、回答待ち。実行中のClaudeを人間の待ち時間と機械の実作業時間に二重計上しない。

## 集計
- 所要時間は開始から終了までの経過時間。実稼働時間とは区別する。
- 未終了区間は観測時点までの経過と表示し、終了時刻を埋めない。
- 内訳不明は独立区分。現在のa2の全時間を「調査時間」にしない。
- 並列子担当の時間合計と、親作業の所要時間は別指標。重複区間を総待ち時間へ足さない。
- 差戻しは同作業の新しい区間として回数と所要時間を残す。
- 3分周期確認では状態遷移・開始/終了が変わった時だけイベントを追加し、同じID/attempt/観測内容を重複保存しない。現在値の観測時刻・未終了経過時間は更新する。
- 完了作業が5件たまった時点または開発終了時に、工程別の既知所要時間・待ち理由・差戻し回数・不明時間の割合を比較する。少数例や不明時間だけでボトルネックを断定しない。

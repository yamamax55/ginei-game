## 1. 既存の入力実装レビュー

盤面（艦隊選択・右クリック）と UI（ボタン）は**別の経路**を通ります。ここが症状の非対称を生みます。

| 経路 | 読み方 | 関門 |
|---|---|---|
| 盤面（`FleetCommander`） | `Mouse.current` を**直接**読む | **2つの早期 return**（下記） |
| UI（`Button`／停止ボタン） | EventSystem → `GraphicRaycaster` | `FleetCommander` の関門を**通らない** |
| Unity メニュー・ネイティブダイアログ | OS 側 | アプリの入力とは無関係 |

### `FleetCommander.Update` の先頭にある2つの関門

```csharp
// FleetCommander.cs:258
if (Time.timeScale == 0 && !PauseManager.IsActivePauseInputAllowed) return;   // 関門1

// FleetCommander.cs:262
if (BattleViewport.Active && !BattleViewport.IsFocused(gameObject.scene)) return;  // 関門2
```

どちらかで `return` すると、**艦隊の選択も右クリックも一切届きません**。
例外もログも出ないので、外からは「入力が消えた」ようにしか見えません。

### 今回の診断で埋まっていなかった穴

`fleet-formation-input-recheck-20260910.txt` は
EventSystem・デバイス・focus・関門1（`アクティブポーズ入力可=True`）まで出していますが、
**関門2（`BattleViewport`）を出していません**。
また「停止ボタンの到達回数 0」はボタン内部の計数で、
そのとき `ポインタが上にある=False`（座標 880,131.5）なので、
**生の入力が来ていない証明にはなりません**（依頼書の指摘どおり）。

## 2. 気づいた点（**原因とは断定していません**）

コードを読んだ範囲で、関門2 が立ちっぱなしになりうる経路があります。**未確認の仮説**です。

- `BattleViewport.Active` は **static**。立てるのも落とすのも `BattleDirector`（戦略の窓会戦）だけ
- `BattleViewport` に**自動リセットが無い**：`RuntimeInitializeOnLoadMethod` も
  `sceneLoaded` / `sceneUnloaded` フックも無し
- `BattleDirector` に **`OnDestroy` が無い**。`BattleViewport.Clear()` は
  「窓を閉じたとき」「窓が全部無くなったとき」だけ
- QA の導線は **Strategy を Play → QA メニュー → `LoadScene("Battle")`（単独ロード）**

したがって、**戦略で会戦ウィンドウを開いてフォーカスしたまま**フルスクリーン会戦へ遷移すると、
`Active = true` ／ `FocusedScene` = 破棄済みの旧シーン のまま残り、
新しい会戦の `FleetCommander` は関門2 で毎フレーム `return` する、という状態が**理屈の上では成立します**。

この仮説は観測されている非対称と噛み合います。

| 事実 | 仮説との整合 |
|---|---|
| 艦隊選択・ドラッグが無反応 | 関門2 の内側なので遮断される |
| 停止ボタンは押せた回がある | 関門2 を通らない経路なので影響を受けない |
| Unity メニュー・ダイアログは通る | OS 側なので無関係 |
| 前の会戦では陣形メニュー指定が成功 | その回は窓会戦を開いていなければ `Active=false` |

**ただし、その Play セッションで実際に窓会戦がフォーカスされたかは分かりません。**
`Active` が false だったなら、この仮説は外れです。だから下記の観測で white/black を付けてください。
製品側の修正は**この観測で裏が取れてから**にしたく、今回は入れていません
（無根拠に入力設定や static のリセットを足さない、という依頼の方針に従いました）。

## 3. 追加した観測手段（読み取り専用・Editor QA 限定）

### (a) 既存の入力診断に関門2 を追記

`Ginei/QA: 入力診断 EventSystem とボタンの状態を出力（Play中）`

```
■ 盤面入力の関門（FleetCommander）
  関門1 timeScale==0 && !アクティブポーズ入力可 → 通過 / ★遮断
  BattleViewport.Active=…　FocusedScene=…　PointerInside=…
  [0] シーン=Battle　関門2 窓フォーカス → 通過 / ★遮断　選択中=N 隊　移動先待ち=…　攻撃目標待ち=…
```

関門2 が `★遮断` なら、その場で**盤面入力が捨てられている**ことが確定します（1行で決着）。

### (b) 生入力の有限履歴レコーダ

`Ginei/QA: 入力診断 生入力の記録を開始／停止（Play中）`
`Ginei/QA: 入力診断 生入力の記録を出力（Play中）`

Play の**フレームごと**に、押下／離上／右押下／選択数の変化があったときだけ1行残します（上限240行・古いものから破棄）。

| 記録項目 | 用途 |
|---|---|
| フレーム・`unscaledTime`・`timeScale` | 押下と離上のフレーム差（短時間クリック／ドラッグ判定） |
| 座標 | 押下〜離上で 10px 以上動けばドラッグ扱い（`pixelDragThreshold`） |
| `IsPointerOverGameObject` ・直下の UI 名 | UI の重なりが食っていないか |
| 関門1／関門2 | 盤面で捨てられていないか |
| 選択数 | クリックが届いたのに選択が変わらない、を見分ける |

**記録するだけ**で入力にも状態にも触れません。Editor アセンブリにあるので製品には入りません。

### 読み取りの指針（出力の先頭にも同じ説明を出します）

| 記録の出方 | 意味 |
|---|---|
| `[左押下]`/`[左離上]` が**1件も無い** | 生の入力がアプリへ届いていない ＝ **自動入力の制約** |
| 押下/離上はあるが `関門2=遮断` | **BattleViewport が立ったまま**で盤面入力が捨てられている |
| 押下/離上・`overUI=False`・`直下=なし` なのに `[選択変化]` が続かない | 関門を通過した先の選択判定の問題 |
| 押下と離上で座標が 10px 以上動く | クリックでなく**ドラッグ**扱い（`onClick` が飛ばない） |
| `overUI=True` で直下に別の UI | UI の重なりが食っている |

## 4. 最小の観測手順（次に Unity を触るとき）

1. これまでと**同じ導線**で再現する（Strategy を Play → `Ginei/QA: 指揮権限 検証会戦を開始`）
2. `Ginei/QA: 入力診断 EventSystem とボタンの状態を出力` →
   **「盤面入力の関門」の3行**（`関門1` / `BattleViewport.Active` / `関門2`）を控える
   - ここで `関門2 → ★遮断` なら**この時点で原因が確定**します。3へ進まず報告してください
3. `Ginei/QA: 入力診断 生入力の記録を開始` → 問題の操作（艦隊クリック、通知のドラッグ）を **3〜5回**
   → `Ginei/QA: 入力診断 生入力の記録を出力` → Console の全文を控える
4. 記録が**空**なら生入力が届いていない＝自動入力の制約。手動クリックで同じ操作を1回試して切り分け
5. 終わったら `生入力の記録を開始／停止` をもう一度実行して記録係を消す

### もし関門2 が原因だった場合の想定対処（今回は未実装）

`BattleViewport` に会戦シーンのロード／アンロード時のリセットを足すのが最小修正になります。
ただし `BattleDirector`（窓会戦）の正常動作を壊さない形にする必要があるので、
**観測で裏が取れてから**、根拠つきで別 task_id にてお願いします。

## 5. 残る本来のQA の UI 手順

入力が通る状態（上記2で関門が両方「通過」）を確認してから実施してください。

### (A) 自然敗走の継続

作業票の注意どおり、敵から離れた非交戦艦は士気0が最初の進行フレームで回復します
（`FleetMorale`：非交戦が `routedRecoveryDelay` 4秒続くと `recoveryRate` で回復）。
**交戦中の艦**で確認してください。

1. `Ginei/QA: 指揮権限 検証会戦を開始` → Space で再開
2. `QA自軍1` に「陣形 ▸ 円陣」→ HUD「円陣（保持・直接命令）」
3. **敵と交戦させたまま**放置し、被弾で士気が落ちるのを待つ
   （`Ginei/QA: 陣形保持 検証会戦の状態を出力` で `敗走=True（士気 0）` を確認）
4. 期待：「陣形保持を解除しました（敗走）」の通知と、状態出力で `保持=False`
5. **交戦中なので自然に敗走が続きます**（QA の `recoveryRate=0` は PlayMode 用の試験入力で、
   実機のこの手順では使いません）

### (B) 支援受諾の通知と費用

1. `Ginei/QA: 支援要請 他軍団を協力的にする（承諾の再現）` → Space で再開
2. `QA他軍1` を選択 →「陣形 ▸ 方陣」→ 系統外なので**要請**になる
   （「…へ陣形変更を要請しました」）
3. 数秒後「応じました」→ `Ginei/QA: 陣形保持 検証会戦の状態を出力`
4. 期待：`保持=True` / `指定元=支援要請` / HUD「方陣（保持・支援要請）」
5. **費用**：同じ出力の `スキルP` を要請の前後で比較 →
   受理された艦のぶんだけ減っていること（拒否された場合は減らないこと）
6. 通知は流れるので、出力末尾の「直近の通知（陣形・支援）」で文面も照合できます

### (C) 攻撃終了／標的喪失後の保持

1. `QA自軍1` に「陣形 ▸ 円陣」で保持させる
2. 同じ艦隊を選び、右クリックで `QA敵1` へ攻撃を指示
3. `Ginei/QA: 陣形保持 検証会戦の状態を出力` → `手動標的=True` / `override=直接命令` を確認
4. `Ginei/QA: 支援要請 攻撃目標を撃沈する（対象消失の再現）` で標的を消す
5. 期待：`手動標的=False` / `override=なし`（命令終了）になっても
   **`保持=True` / `陣形=円陣` のまま**であること

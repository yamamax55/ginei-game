# Claude Code・ChatGPT 開発手順

制定：2026-09-09。ユーザー合意に基づき、次回の開発から適用する。文書の更新だけでは、終了中の開発や自動報告を再開しない。後から示されたユーザーの指示を優先する。

## 基本方針

「仕様確定 → 実装 → 統合 → 実機検証」を、遊べる一つの機能単位で繰り返す。各段階の完了条件を満たしてから次へ進む。テスト合格・実装完了・実機確認済みを同じ意味で扱わない。

## 役割分担

|担当|責任|
|---|---|
|ユーザー|ゲーム像、重要な仕様と優先順位、節目での面白さ・操作感の判断|
|Claude Code|コード調査、実装、必要な自動テスト、並列作業の調整、最終統合|
|ChatGPT|要件・合格条件の整理、Blender制作、実画面検証、不具合の再現整理、進捗・文書更新|

ゲームプログラムの修正はClaude Codeに一本化する。ChatGPTはコードを読み取って調査できるが、ゲームコードを独自に修正しない。

## 1. 仕様確定

ChatGPTが、目的、対象範囲、操作の流れ、期待する結果、合格条件を短い作業票にまとめる。戦略・戦術・保存への影響を必要に応じて含める。
既にユーザーが指示した内容を繰り返し承認依頼しない。重要な仕様が曖昧な場合だけ確認し、通常の実装判断は担当側で進める。

完了条件：Claudeが実装対象と合格条件を理解でき、未確定事項が対象の実装を妨げない。

例：要塞への駐留

- 艦隊メニューから味方要塞へ駐留し、出撃できる。
- 駐留・出撃で艦艇数と指揮官が変わらない。
- 星系と要塞で同じ艦隊を二重集計しない。
- 防衛戦の損害が元の艦隊に反映される。
- 敵に占領されても駐留艦隊が自動的に敵の艦隊へ変換されない。
- 保存・読込後にも駐留状態が一致する。

## 2. 実装

Claudeが実装し、変更に必要なテストを行う。独立する作業は並列化できるが、担当範囲と共有データの接続方法を先に決める。同じファイルへの同時編集を避け、最終統合の責任者はClaude側で一つにする。
ChatGPTはこの間、素材制作や検証手順の準備を進められる。編集中の版で実機合格を判定しない。

完了条件：担当範囲の実装と必要なテストが終了し、変更点・制約・未完了事項を統合担当へ渡せる。

## 3. 統合

Claudeが並列作業をまとめ、コンパイルと関連する回帰テストを実施する。画面、戦略と戦術の往復、データ保存などの接続を確認する。
実機検証へ渡す際は、次を明記する。

- 検証対象の版、変更範囲、編集停止時刻。
- テスト結果と実行範囲。未実行のテストや既知の制約。
- 起動方法と検証用シナリオの作り方。
- 元のセーブや既存変更を守るための注意点。

コミットしない作業でも、検証番号と時刻、対象ファイルの一覧・差分などで対象を識別する。無関係な変更をまとめてコミットしない。

完了条件：統合後の必要なチェックが通り、対象の編集が止まり、ChatGPTが同じ版を再現して検証できる。

## 4. 実機検証

ChatGPTが合格条件に沿って、統合された版を操作する。単一画面だけでなく「編成 → 移動 → 戦闘指揮 → 占領 → 損害反映・帰還」など、変更が影響する流れを確認する。
結果は「合格・不合格・未検証・入力制約で判定不能」に分ける。自動入力の不達をゲームの不具合と断定しない。実マウス・実キーボードによる確認とは区別する。

不具合は、再現手順、期待結果、実際の結果、対象版、画面やログをClaudeへ渡す。修正時は検証を区切り、「実装 → 統合 → 実機検証」へ戻る。版が変わったら、影響する合格条件を再確認する。

完了条件：対象の合格条件を確認し、残件と制約が明示されている。必須条件が未検証なら「検証完了」としない。配布する場合はビルドと起動確認も行う。面白さ・操作感は節目でユーザーのプレイ評価を受ける。

## 途中の仕様変更と終了

追加依頼は作業票に追記し、現在の作業への影響を判断する。仕様変更が合格条件を変える場合は仕様段階へ戻して対象を更新する。小さな追加は次の作業単位へ回すなど、編集と検証を混在させない。

ユーザーが終了を指示したら、新しい実装・検証を始めず、現在の段階、対象版、確認済み、残件、次の一手を引継ぎに残す。再開時はその記録と最新指示を確認する。

## 共通の作業票

- 作業名・目的：
- 現在の段階：仕様確定／実装／統合／実機検証／完了／中断
- 対象範囲・今回扱わない範囲：
- 仕様・合格条件：
- Claudeの担当範囲・並列作業の分担：
- 検証対象版・編集停止時刻：
- 自動テスト結果と報告者：
- 実機検証結果と証拠：
- 未確定事項・残件・次の作業：

進捗ページと引継ぎには、この作業票の要点を反映する。「実装完了・実機検証待ち」のように現在の状態が分かる表記にする。

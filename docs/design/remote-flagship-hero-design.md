# 遠隔座乗・操作のMOBA化 設計（ヒーロー会戦モードの操作体系）

> MOBA を本作（銀英伝風の星間国家戦略＋戦術艦隊戦）へ落とし込むにあたり、**リスポーン・アイテム購入は見送り**（戦略レイヤーの艦隊消耗と喧嘩するため）、**操作体系を MOBA に寄せる**（1体の旗艦を直接操作＋Q/W/E/R スキル発動）方向に集中する。ヒーロー会戦モード EPIC #2747／会戦中の旗艦成長 #2757／LoL EPIC #2739 の延長。lore＝`docs/lore/設定/遠隔座乗.md`。**本書は設計のみ（実装はまだ）**。
> 著作権注意：MOBA のメカニクス/構造のみ参考（固有名は不使用）。

> **方針転換（2026-06）**：当初検討した「リスポーン（予備旗艦の遠隔再投入）」「戦功ショップ（会戦限定の換装購入）」は、艦隊の消耗を核とする戦略レイヤーと擦れるため**見送り**（HERO-8 #2760／HERO-10 #2762 クローズ）。本書はその記録と、残す要素（操作MOBA化・敗北条件・能力合成）の設計。

---

## 0. コンセプト：遠隔座乗（lore の鍵）

提督は旗艦に物理搭乗せず、**根拠地の管制宝座〈感応座〉から旗艦を遠隔操作する**（旧・大環状連合の遺産技術）。これにより：

- **旗艦撃沈 ≠ 提督の死**（提督は根拠地で無事）。撃沈は退避/指揮復帰の帰結（リスポーンはしない）。
- **1体の旗艦を「我が手足のごとく」直接操作**できる理由付け＝MOBA 的な単機操作と俯瞰視点が lore 整合する。
- **根拠地を失えば**遠隔の繋がりも提督の身柄も失う＝提督の撤退/死亡/捕縛＝真の「死」。

---

## 1. 操作体系の MOBA 化（直接操作＋Q/W/E/R スキル）

MOBA の最も深い魅力は「1体の直接操作＋スキルの撃ち合い」。リスポーン/ショップ抜きでこれを載せる。

- **直接操作**：ヒーロー旗艦を右クリック移動＋左クリック対象指定で駆る。カメラは**ヒーロー追従**。RTS 全体指揮とシームレス切替（HERO-2 #2749）。`FleetCommander.SelectedFleets`（選択の単一窓口）と Esc 優先順位チェーンを崩さない。
- **Q/W/E/R スキル発動**：戦法（`ActiveCommandRules`#2175）・号令（SGT-2）を **Q/W/E/R の4スキル**（3基本＋必殺 R）に割付け、采配ゲージ（SGT-1）消費で**即発動**。アビリティバー HERO-4 #2752。
- **キー衝突の解消**：**WASD は会戦カメラ移動**（`CameraController`）。ヒーロー没入モード中はカメラを追従に切替え、`GameInput`(#107) の**会戦コンテキスト**で QWER をスキルへ割当（`GameInput.SetContext`／衝突は `FindConflicts` で EditMode 担保）。`Keyboard.current` 直読みを増やさず `GameInput` に集約。
- **全旗艦がヒーロー**：全旗艦が遠隔操作のヒーロー（プレイヤーは"今操作する1隻"に集中・AIも同枠組み・HERO-1/3 の一般化）。オフスクリーン/非係争は LOD 抽象（`AutoBattleSim` 寄せ）でPERF確保。

## 2. 根拠地 ＝ 敗北条件（喪失で提督の撤退/死亡/捕縛）

- **根拠地**＝保有星系（`PlanetSiegeRules` の攻防対象）。MOBA の base に相当するが、**再投入アンカーではなく「敗北条件」**として残す。
- **喪失＝敗北＋提督の運命**：敵に根拠地を制圧されると遠隔操作不能＋提督（感応座に在る）の**撤退/死亡/捕縛**を判定（`PersonnelFateRules`/`CaptivityRules`/`SurrenderRules`/`EncirclementRules`/`SutegamariRules` 系へ橋渡し）。撤退/死亡/捕縛は統率・謙虚さ・戦略状況・敵の追撃/包囲度で決まる決定論 roll。
- HERO-9 #2761。「旗艦は何度でも沈むが、根拠地と提督の命は一つ」。

## 3. ~~戦功ショップ~~（見送り）

会戦限定の専用通貨「戦功ポイント」で再補給拠点の換装を買う案は、**会戦限定の別台帳でも戦略レイヤーと擦れる**ため見送り（HERO-10 #2762 クローズ）。永続の艦強化は従来どおり造船/R&D（`ArmamentDesignRules`）が担う。カウンタービルドの妙は、戦法（QWER）の選択と陣形（#72/#2177）で出す。

## 4. 階級投入コスト ＋ 最終能力合成式

- **階級が高いほど会戦への投入コストが重い**（精鋭を全戦線に撒けない）。新Core `DeploymentCostRules`（コスト＝階級の関数）。`RankSystem`／`FleetCapRules`／SGT-7 出撃コスト（#2727）と接続＝**SGT-7 と二重定義しない**。
- **最終能力＝合成式**：旗艦の実効戦闘力を **`階級 × 提督能力 × 戦略状況 × 旗艦`** で決める（`ModifierStack` で積む・各成分は既存窓口へ委譲＝二重実装しない）：
  - **階級** → 指揮影響圏 GIR-1 `CommandAuraRules`／指揮容量 `CommandCapacityRules`
  - **提督能力** → `CombatModifiers.AbilityFactor`（既存）
  - **戦略状況** → 補給/士気/国力差/中立目標バフ LOL-1/厭戦（`WarWearinessModifiersRules` 等）
  - **旗艦** → 艦種 `ShipClass`#80 ＋ 会戦内成長 #2757
  - 新Core `FlagshipEffectivePowerRules`（合成の単一窓口）。HERO-11 #2763。

## 5. 既存システムへの接続（作り直さない）

| 要素 | 接続先（既存） | 新規（薄い Core） |
|---|---|---|
| 直接操作＋QWERスキル | `ActiveCommandRules`/SGT-1/SGT-2/`GameInput`#107/`FleetCommander` | （Game配線・新Coreなし） |
| 根拠地喪失→提督の運命 | `PlanetSiegeRules`/`PersonnelFateRules`/`CaptivityRules`/`SurrenderRules`/`SutegamariRules` | （判定オーケストレータのみ） |

| 最終能力合成 | `CombatModifiers`/`ModifierStack`/GIR-1/LOL-1/#2757 | `FlagshipEffectivePowerRules` |
| 被撃破帰結（リスポーンなし） | 捨てがまり/敗走解決/LOL-3 賞金首 | `HeroStakesRules`（HERO-6 #2754） |

## 6. 未決の論点（実装前に決める）

1. **根拠地喪失の運命 roll の係数**（撤退/死亡/捕縛を統率・謙虚さ・戦略状況・包囲度のどれでどう引くか）→ HERO-9。
2. **戦略状況の合成への入れ方**（補給/士気/国力差/中立目標を1つの倍率に畳む・レンジ定義）→ HERO-11。
3. **階級投入コストの数値**（階級×コスト曲線・出撃予算・SGT-7 との重複整理）→ HERO-11。
4. **QWER のスキル設計**（どの戦法/号令を4枠に・クールダウン/采配ゲージ配分・スキルショット的な照準の有無）→ HERO-4。
5. **AI/PERF**（全旗艦ヒーロー化＝係争会戦のみ精密・他は `AutoBattleSim` 抽象＝観測解像度とシミュ解像度の分離・PERF#1117）。

## 7. 規律
- **lore**：遠隔操作＝単機の直接指揮の理由付け（蘇生でなく退避／根拠地の命）。 **タイクン/ラグ回避**：新規 Core は薄く（リスポーン/ショップを増やさない）。 **二重計上回避**：効果は既存窓口へ委譲（ActiveCommand/采配ゲージ/CombatModifiers）。 **雪だるま**：賞金首(LOL-3)＋能力上限クランプ。 **入力は単一窓口**：`GameInput`(#107) に集約・Esc/選択の規約を崩さない。 **合成は単一窓口**：`ModifierStack`/`CombatModifiers`。

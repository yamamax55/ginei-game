# 開発ログ 2026-06-20 ── Blenderで戦艦を3D化（MCP連携・噴射アニメ）とBlender→Unity知見の文書化

ゲームロジックではなく**アート/制作パイプライン**に寄った日。提供された戦艦イラストを **Blender MCP** 経由で 3D 化し、流線型化→高層化→エンジン噴射アニメまで反復。成果物を2本のPRに整理し、Blender→Unity の現実的な落とし穴を設計ドキュメント化した。**現状はR&D寄りで、ゲーム本体への実投入は未**（艦船は今も2Dスプライト運用）。

## 1. Blender MCP セットアップ／接続
- 前セッションで導入済みの `blender-mcp`（uvx 起動・user スコープ・アドオン永続化）を本セッションで接続確認。`mcp__blender__*` が `ToolSearch` 経由で利用可能に。
- Blender 5.1 側で「Connect to Claude」（ポート9876）→ `get_scene_info`/`execute_blender_code`/`get_viewport_screenshot` の往復が成立。
- **5.1のAPI差分**に遭遇：`object.delete(use_confirm=...)` 廃止、スムーズシェードは `shade_smooth_by_angle` 推奨。Poly Haven 等の外部連携は後回し方針のまま。

## 2. 戦艦の3D化（手続き生成・約300→約600パーツ）
- 上面ビューのスプライトを前提に、**Pythonで手続き生成**（左右対称をオブジェクト複製で実現）。船体→上部構造→砲塔→ブリッジ→エンジン→推進炎の順に積層。約**307パーツ**でイラストのシルエットに到達。
- マテリアルは8種（船体ダーク/メタル/シルバー縁/発光青/赤標識/エンジン発光/炎）。**全て手続き＝外部テクスチャ依存なし**。

## 3. 流線型化・高層化・噴射アニメ（反復）
- **流線型化**：構造パーツ191個にベベル（2分割・凸プロファイル）＋角度付きスムーズ。一旦16k頂点まで増えたため Decimate で約2倍（5.3k→9.9k）に調整。
- **高さ3倍化**：箱状マスはZ伸長、砲身/ノズル/炎（X90°回転パーツ）は伸ばさず位置だけ引上げて比率維持。空いた縦空間に約**300パーツ追加**（指令タワー多段・副タワー・縦リブ・デッキバンド・配管・側面プラットフォーム＋小型砲・レーダー/アンテナ群・縦エンジンスタック・窓灯）。総**616パーツ／14.4k頂点**。
- **エンジン噴射**：ノズル出口にエミッター円盤を置き、発光小球を後方(-Y)へ放出する**パーティクル6系統**（メイン4＋サイドポッド2・重力0・寿命16f・frame 1–120）。

## 5. 学び（Blender→Unityの現実）
- **持ち出せないもの**：Blenderの**パーティクルと手続きマテリアルは FBX/glTF に乗らない**。噴射はUnity側 VFX、材質はURP Litで作り直す前提。
- **アニメの分担**：噴射=Unity VFX／砲塔=スクリプト回転（Slerpで照準追従）／変形=ボーンFBX。Blenderからは**形・ピボット・マーカー(Empty)**だけ持ち込む。
- **配信形態**：リポジトリは `.blend` 直よりも **FBX/glTF** が堅い（Blender非依存）。Unityの **.meta は初回インポートで自動生成→要コミット**。
- **画面に重ねるムービー**：背景透過が必須＝**mp4(H.264)単体は不可**。手軽さなら WebM(VP9 alpha)、負荷耐性＋全環境なら **H.264＋パックアルファ**（シェーダー再合成）。`VideoPlayer` は裏処理のスパイクに間接的に引っ張られるが、**`timeScale=0`でも再生継続**するため**演出中はsim停止**が最も確実。

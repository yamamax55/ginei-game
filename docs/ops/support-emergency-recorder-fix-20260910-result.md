## 原因

`SupportEmergencyQaMenu` の観測期間を **`Time.realtimeSinceStartup`（実時間）** で測っていました。
実時間は次のあいだも進みます。

| 場面 | 実時間 | 会戦の進行 |
|---|---|---|
| `EditorUtility.DisplayDialog` を開いている間（Play ループごと停止） | **進む** | 止まる |
| 一時停止中（`timeScale = 0`） | **進む** | 止まる |
| Unity を止めている間 | **進む** | 止まる |

誘発コマンドは「入力条件を変える → **ダイアログを出す**」という流れなので、
テスターがダイアログを閉じて Space で再開するころには 10 秒を使い切っており、
**3 行だけ記録して「中断なし／撤退なし」** と表示していました。
実機報告のとおり、これは検証を妨げる QA 側の欠陥です（製品の不具合ではありません）。

フレーム側も `Time.frameCount` の差で数えていたため、
「最初の 6 フレーム」が一時停止中のフレーム（`Update` は回るが盤面は進まない）で消費されていました。

## 修正（QA記録のみ・製品コードは触っていない）

対象は `Assets/Editor/SupportEmergencyQaMenu.cs` の 1 ファイルだけです。
**製品 AI・入力処理・`DamagePopup` は変更していません。**

### 1. 時間軸を「会戦が進んだぶん」に変えた

`Time.time`（timeScale 追従・停止中もダイアログ中も進まない）の**増分を積算**します。

```csharp
float now = Time.time;
if (now <= watch.lastBattleTime)   // 盤面が止まっている
{
    // → 「再開待ち」。観測期間を一切消費しない。
    return;
}
watch.progressSeconds += now - watch.lastBattleTime;
watch.lastBattleTime = now;
watch.progressFrames++;
```

- 観測期間 `RecordBattleSeconds = 10f` は **会戦が 10 秒ぶん進むまで**の意味になりました
- 記録間隔 `SparseInterval = 0.25f` も **会戦の進行 0.25 秒ごと**
- **最初の 6 フレーム**は `progressFrames`＝**実際に盤面が進んだフレーム**だけを数えます

### 2. 倍速の扱い（明示）

`Time.time` は `timeScale` に追従するので、**2 倍速なら実時間の半分で同じ「会戦 10 秒ぶん」**を観測して終わります。
数えているのは実時間ではなく**盤面が進んだ量**なので、**倍速でも観測できる会戦の長さは変わりません**
（実時間だけが短くなる）。この説明は記録の見出しにも出力します。

### 3. 状態を4つに分け、未観測を合否と断定しない

```csharp
private enum RecordState { 記録中, 再開待ち, 完了, 打ち切り }
```

| 状態 | 意味 |
|---|---|
| `記録中` | 会戦が進んでいて記録できている |
| `再開待ち` | 盤面が止まっている（一時停止・ダイアログ・Play停止）＝**観測期間を消費しない** |
| `完了` | 観測期間ぶん会戦が進んだので締めた |
| `打ち切り` | 会戦が進まないまま安全網で畳んだ＝**判定材料にならない** |

出力の文言も、単なる「あり／なし」から次のように変えました。

- `観測あり`
- `観測なし（会戦は進んだ）` … 会戦が 10 秒ぶん進んだうえで起きなかった＝**要確認の材料になる**
- `未観測（会戦がまだ進んでいない）` … **合否の材料にならない**

`完了` でないときは
**「★この記録だけで合否を決めないでください」**＋再開の案内を、Console とダイアログの両方に出します。
これで前回のような「停止中だけの結果を不合格と読む」事故が起きません。

### 4. 「再開待ち」を1行だけ残す

止まっているあいだ記録が無音にならないよう、
`[再開待ち] 盤面が止まっています（timeScale=0.0）。観測期間は消費していません。Space で再開すると記録を続けます。`
を **1 行だけ**入れます（毎フレーム積み上げない）。

### 5. 安全網

観測期間は会戦時間で測るので、Play を止め忘れたまま放置するとフックが残り続けます。
そこで **実時間 600 秒**を超えても会戦が進まない場合だけ `打ち切り` で畳みます。
これは観測期間ではなく後始末で、`打ち切り` は判定材料にしません。

### 6. 誘発ダイアログの文言

「10 秒間、自動で記録します」→
**「★Space で再開してください。記録は<会戦が進んだぶん>で 10 秒たまるまで続きます（一時停止中・このダイアログ中は観測期間を消費しません）」**

### 変えていないこと

- **誘発前／直後の前提記録**（`Sample("誘発前")` と `Sample("誘発（…）")`）はそのまま保持
- 誘発が触るのは**入力条件だけ**（敗走＝士気、総退却＝残存兵力）
- **AI 状態・override・移動先を QA から書き換えない**方針は不変
- 前提が未成立なら何もせず**【未成立】**を出す動作も不変

## 実機手順（ChatGPT へ）

前回と同じ準備で、**記録が再開待ちで消えないこと**を確かめてください。

1. Unity Play → `Ginei/QA: 指揮権限 検証会戦を開始（戦役・Play中）` → 準備完了ダイアログを閉じる
2. `Ginei/QA: 支援要請 他軍団を協力的にする（承諾の再現）`
3. Space で再開 → `QA他軍2` に遠方への移動を要請 → 「応じました」を確認
4. `Ginei/QA: 緊急中断 他軍団を総退却の兵力まで減らす（Play中）`
5. **ここでダイアログをしばらく開いたままにし、閉じたあとも数十秒そのまま停止しておく**
6. `Ginei/QA: 緊急中断 記録を出力（Play中）`
   - **期待**：記録の状態＝`再開待ち`、会戦の進行＝ほぼ `0.00 / 10 秒`、
     中断・撤退とも **`未観測（会戦がまだ進んでいない）`**、
     「★まだ判定できません」が出ること。**「観測なし」と断定しない**こと。
7. Space で再開して会戦を進める
8. もう一度 `記録を出力`
   - **期待**：状態＝`完了`、会戦の進行＝`10.00 / 10 秒` 付近、
     中断＝`観測あり`、撤退状態＝`観測あり`。
     時系列に `+1F（進行）`〜`+6F（進行）` と `+n.nns（会戦時間）` が並び、
     停止中のあいだは `[再開待ち]` 行が 1 本だけ入っていること。
9. **倍速の確認**：`2` キーで 2 倍速にして同じ誘発を行う
   - **期待**：実時間はおよそ半分で終わるが、会戦の進行は同じ `10.00 / 10 秒` に達すること。

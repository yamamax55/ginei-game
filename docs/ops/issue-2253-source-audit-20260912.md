### 現状と根拠

### 調整方針
会戦の操作感を維持し、直接指揮は自分の指揮系統内に限定する。他軍団には要請し、相手が承諾した命令を実行する。全艦隊には旗艦があり、軍団は複数の艦隊を束ねる。軍団コマンドによる集中・展開・陣形・撤収が戦果を左右する構成にする。

### 優先順と受け入れ条件
- [ ] **P0 命令の優先順位・所有者**：直接命令／受諾済み要請／軍団命令／自律AIの競合を整理する。移動は指定先まで維持し、勝手な上書き・振動を防ぐ。完了・取消・対象消失でAIへ復帰する。
- [ ] **P0 緊急退却**：受諾済み支援命令が敗走・総退却を妨げない。既存の直接命令の仕様変更とは区別し、中断理由を記録する。
- [ ] **P0 攻撃の一連の動作**：射程外なら指定敵へ接近し、射界・間合いを調整して攻撃する。無関係な敵への接近、停止したままの待機、撃沈済み目標への固着を防ぐ。
- [ ] **P1 陣形の保持**：軍団・艦隊への明示的な陣形指定を自動切替が直後に覆さない。保持の単位と解除条件を明示し、直接命令と承諾済み要請の両方で検証する。
- [ ] **P1 軍団連携**：集結・集中攻撃・側面展開・予備隊・撤収を軍団単位で実行し、艦隊がばらばらに逐次投入されない。所属外の艦隊へ直接命令が漏れない。
- [ ] **P1 要塞・回廊**：守備側は要塞と駐留艦隊・浮遊砲台を活用し、攻撃側は危険域へ無謀に突撃しない（#641、#40）。戦術上迂回できない回廊では、存在しない迂回路を選ばず、待機・戦力集中・撤退等を判断する。
- [ ] **P2 個性・難易度**：まず命令の正しさを固め、その後に提督ごとの判断・反応・集中・撤退閾値を調整する（#642）。難易度による違いを同条件の会戦で比較する。
- [ ] **P2 判断の見える化**：現在の命令、命令元、指定先/目標、実行中/中断/完了と理由を診断できる。座標・残距離・AI状態を記録し、承諾通知だけを完了証拠にしない。

停止→命令→再開、倍速、承諾/拒否/期限切れ、到着、標的撃沈、敗走/総退却、軍団再編、密集戦、要塞防衛を確認する。指定先・残距離・命令維持・AI復帰を時系列で照合する。小さいヘルパーの真偽だけでなく、命令受付から移動/攻撃と解除までの統合テストとUnity実機検証を実施する。

## 2026-09-10 艦隊陣形変更のコード調査・改善案

| 高 | FleetCommander.ChangeFormation は Squadron.TryChangeFormation を呼ぶが、陣形専用の手動保持を設定しない。FleetAI.UpdateFormationDoctrine や BattlefieldCommandManager の推奨陣形で再変更され得る。移動等のManualOverrideや手動軍団隊形によって抑止される場合もあるため、常に上書きされるという断定はしない。 | 陣形の指定元・手動保持・解除を独立管理。直接指定と承諾済み要請を、移動命令終了後も適切に維持する。 |

### 1. 陣形専用の保持・解除と命令の優先順位

- 各艦隊に指定陣形、指定元、手動保持／自動を持たせる。陣形指定は移動・攻撃命令と独立する。
- 変更が受理された時点で保持開始。移動・攻撃の終了、一時停止、倍速で解除しない。
- 「艦隊陣形を自動に戻す」で陣形保持だけを解除し、移動・攻撃命令は継続する。
- ポイント不足・使用資格不足なら拒否し、以前の陣形と保持状態を維持する。自動再試行しない。
- 保持の継続費用はゼロ。同じ陣形の再指定も無料で保持を設定できる。
- 会戦終了で解除。会戦途中保存に対応する場合は保持状態も保存する。

優先順位：
1. **敗走・総退却**：保持を解除し、陣形維持が撤退を妨げないようにする。
2. **明示的な陣形指定**：自軍への直接指定、または受諾済み要請を保持。同一艦隊では最後に受理した指定を優先。他軍団への要請は承諾前に変更しない。
3. **軍団AIの陣形指示**：明示指定のない艦隊に適用。
4. **艦隊AIの自動判断**：明示指定も軍団指示もない場合に適用。

軍団隊形との分離：
- 軍団隊形＝艦隊同士の配置。艦隊陣形＝旗艦配下の艦艇配置。
- 軍団隊形の変更だけでは、各艦隊の指定陣形を変更しない。
- 統一する場合は別操作「配下艦隊の陣形を一括指定」を使用する。
- 「軍団指定を解除」は軍団内配置だけを解除し、艦隊陣形保持は残す。
- 軍団所属の変更時は旧指揮系統による陣形保持を解除する。
- 表示例：艦隊陣形：鶴翼陣／手動保持／指定元：プレイヤー。変更・拒否・解除と理由は艦隊別に表示し、総退却による解除も通知する。

**範囲の区別**：総退却が直接移動・攻撃命令も中断するかは別の命令仕様。本仕様による陣形保持解除だけで、直接移動・攻撃命令の中断まで確定した扱いにしない。

### 2. 艦隊別の変更結果・費用・失敗理由

変更前：陣形メニューに艦隊名、現在→指定陣形、必要／保有ポイント、変更可否・理由を表示する。費用は実際の計算値を使用し、発令時にも再判定する。数値例は固定仕様ではない。

変更後：変更受付／失敗／要請中の隊数を集計し、各艦隊の明細を表示する。
- 変更受付：指定陣形、消費ポイント、残量、保持状態。
- 失敗：ポイント不足、使用資格不足、撤退中など具体的な理由。消費ゼロ、以前の指定を維持。
- 要請中：他軍団への依頼は承諾・実行まで成功に数えない。
- 変更不要：同じ陣形なら消費ゼロ。保持設定の結果を表示する。
- 一部だけ変更可能ならボタンを「変更可能な2隊に指示」など対象数を明示する表記にする。
- 「変更受付」と「形成完了」を区別し、命令受理だけで整列完了を表示しない。

### 3. 形成過程・戦闘効果・自動包囲

- 状態は変更受付→形成中→形成完了。艦艇は速度・旋回性能に従い配置につく。
- 整列度は生存配下艦と各自の配置位置との距離から算出し、撃沈艦を除外する。
- 攻撃・防御・陣形相性の補正を整列度に応じて反映し、形成途中に新陣形の全効果を発動しない。
- 変更開始時は旧陣形の効果から連続的に移行し、旧・新の有利な効果を重ね取りできないようにする。
- 移動・旋回中も指定を保持。配置が崩れれば効果が弱まり、整えば回復する。
- 再変更はその時点の配置・効果から移行し、瞬間移動や効果リセットによる有利な抜け道を防ぐ。
- 完了判定に余裕を設け、微小な揺れによる形成中／完了の頻繁な往復を防ぐ。判定値・移行速度などの数値は会戦調整事項。

自動包囲：
- 陣形保持中は陣形を崩す自動包囲を行わない。艦隊全体の側面への移動は可能。
- 自動陣形中は条件を満たせば包囲へ移行し、「包囲中」と表示する。
- 包囲中は維持していない陣形の補正を適用しない。実際の位置関係による側背面攻撃・集中攻撃は有効。
- 対象消失時は通常の自動判断に戻り、選んだ陣形を形成する。
- 包囲中に手動陣形指定が受理されたら、包囲を解除し指定陣形の形成を開始する。
- 敗走・総退却時は包囲・形成を中断し、撤退を優先する。
- 表示例：鶴翼陣／手動保持／形成中 68%。割合は配置の整い具合であり、火力がそのまま68%という意味ではない。
